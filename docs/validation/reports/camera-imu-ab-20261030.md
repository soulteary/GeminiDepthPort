# 相机 IMU 支持与性能验证（2026-10-30）

基线提交：`4063c689f53d6324ea389b28dddccdc474fb079e`。本次增加显式开启的加速度计与陀螺仪采集，默认关闭。配置示例见 `examples/rust-single-camera/inventory.imu.example.json`，完整语义见 `docs/contracts/camera-imu-v1.md`。

## 功能验证

Rust 生产行覆盖率为 18193/18366（99.06%），未修改覆盖率口径或阈值。Rust 1.85 全套数据平面测试、Clippy 和格式检查通过。SDK 模拟测试覆盖不支持的传感器、启动失败、数据异常、队列溢出、超时、停止失败和迟到回调生命周期。实际 Humble/Fast DDS 验证两路 sensor_msgs/Imu、时间戳、单位、协方差、QoS，以及 ROSbag2 SQLite3 逐消息 CDR SHA-256 读回和有效数值篡改拒绝。原有图像、CameraInfo、元数据、TF 和诊断 smoke 均通过。

内置 files-v2/chunked-v3 录制支持 IMU，保留两轮实际读回、逐帧图像哈希和崩溃恢复；完成条件包含两路 IMU 数据及完整验证。没有姿态融合、插值或未经标定的 IMU 外参。

## 性能方法

共 40 次运行：两种环境，每种环境仅发布/启用原生录制两个场景，每个场景 IMU 开关交替运行各 5 次。模拟 SDK 图像为 640×400、YUYV/Y16，名义 30 FPS；加速度计和陀螺仪各 200 Hz。原生录制使用同步 chunked-v3、60 对图像（约 58.59 MiB）。测试入口是忽略执行的 `imu_capture_ab_benchmark` 集成测试。

CPU 统计 worker 与 supervisor 的进程时间之和除以测量墙钟时间；RSS 为两个进程各自峰值之和，既不是同时刻峰值，也不是匿名内存。仅发布场景就绪后测量 2 秒；原生录制场景就绪后测到目标完成。追加 P99 为直方图分位上界，验证耗时取整次录制累计数据，包含就绪前已追加的数据。SDK 轮询统计包含启动阶段；开启 IMU 会前移 ROS 初始化成本，因此不能将轮询 P99 下降解释为稳态改进。

## 结果（5 次中位数，关闭 → 开启）

ARM64 原生执行、模拟 SDK 与模拟发布桥：

- 仅发布：26.9706 → 26.9878 对/秒；CPU 0.0700 → 0.0900 核；RSS 9100 → 9144 KiB。
- 原生录制：27.2890 → 27.5471 对/秒；CPU 0.2001 → 0.2066 核；RSS 11372 → 11164 KiB（负差属于波动，不能认定内存优化）。
- 原生追加 P99：18.226 → 17.751 ms；累计验证：92.038 → 86.920 ms。小幅下降不作为性能收益结论。
- IMU 队列峰值 14/128。

真实 Humble/Fast DDS 发布桥、模拟 SDK，在 ARM64 主机上仿真执行 AMD64：

- 仅发布：15.9924 → 15.9941 对/秒；CPU 0.4549 → 0.4698 核；RSS 90156 → 93724 KiB。
- 原生录制：15.3582 → 15.4900 对/秒；CPU 0.6721 → 0.6907 核；RSS 101464 → 105200 KiB。
- 原生追加 P99：78.780 → 85.886 ms；累计验证：447.941 → 503.230 ms。
- IMU 队列峰值 65/128；所有目标录制完成，各次 IMU 验证计数均为提交样本的两倍。

该组真实 DDS 数据的帧率中位数基本一致，CPU 增量约 0.015–0.019 核，RSS 增量约 3.5–3.7 MiB。两种环境不能互相比较以推导 ROS 开销。没有物理相机、USB、外部 ROSbag2 负载参与性能计时；不能据此承诺实机 30 FPS 或长期无丢失。下一步应在目标相机、原生 CPU 架构和实际录制负载下重复开关对照，检查 IMU 序号/时间戳、队列余量和图像间隔。

原始 40 次观测、分位区间与计数见同名 JSON。实际生产 SDK 镜像本地构建因基础镜像下载停滞未完成；真实 SDK 符号检查由运行时镜像 smoke 在 CI 执行。
