# 录制检查点分段观测与采样开销 — 2026-10-30

基线 `00f667ba24d21c54db9daec66b5b786e23c1212e`。实现及最终构建哈希、每轮结果见[原始 JSON](checkpoint-observation-ab-20261030.json)。实机命令及字段解释见[采样说明](../../development/checkpoint-observation.md)。

新增 `raw_recording.checkpoint_observation`，默认关闭，诊断录制显式设置为 `true`。12 类分段分别记录墙钟和线程 CPU；保留 64 条完成事件和最多 4 条活跃事件，以单调时钟、检查点 ID、进程/线程 ID 与队列、磁盘统计和可选 perf 栈关联。记录只保存在内存/现有状态输出，不新增逐帧日志。

观测不改变落盘格式、哈希、校验器、提交守卫或确认顺序。V3 仍逐帧验证已封口前缀，再最终实际全量读回；两轮图像和 IMU SHA256 校验均保留。files-v2 保持原有最终验证，不声称新增第二轮。

## 测量方法

Linux ARM64 Docker，Rust 1.90 release。4 种模式各 5 次，逐轮反转执行顺序，共 20 次独立采集。每次 640×400，180 对，视频 wait 延迟 33 ms，两路合成 IMU 各请求 200 Hz，chunked-v3 检查点流水线、录制队列容量 4。基线和新版本使用同一测试驱动/合成 C SDK 与 ROS C ABI 桥；没有 USB、真实 DDS、真实相机或 ROSbag2。模拟库在计时窗口之前构建，计时期间没有并行编译或其他测试。

CPU 为 readiness 到原生录制 complete 的 worker 与 supervisor CPU 增量之和除以墙钟。墙钟不含启动；不是无限制写入吞吐测试。RSS 为 worker 从启动至该点的 VmHWM，并非匿名内存或两进程同时峰值。追加 P99 是固定直方图区间；验证耗时累计前缀及最终读回墙钟，可能与追加重叠。所有数值为五轮中位数。

## 最终构建结果

- 基线：CPU 0.2193 核；完成窗口 6.613 s；追加 P99 [3.932, 4.194] ms；验证 291.48 ms；worker RSS 8656 KiB。
- 新版本，观测关闭：CPU 0.2161 核；完成窗口 6.652 s；追加 P99 [3.670, 3.932] ms；验证 275.72 ms；worker RSS 8672 KiB。
- 新版本，观测开启：CPU 0.2524 核；完成窗口 6.578 s；追加 P99 [3.408, 3.670] ms；验证 263.25 ms；worker RSS 9256 KiB。
- 观测开启并运行基本采样：CPU 0.2336 核；完成窗口 6.511 s；追加 P99 [2.884, 3.146] ms；验证 245.19 ms；worker RSS 9184 KiB。

基本采样脚本自身：0.0079 核，RSS 13268 KiB，每轮 JSONL 约 211.3 KiB。5 轮没有诊断事件遗漏，队列高水位均为 1，对照各轮也没有录制队列溢出。

关闭观测相对基线 CPU 变化约 -1.5%；开启观测额外约 0.0363 核。它不是零成本功能，因此默认关闭。开启观测再加入采样，采集进程 CPU 变化约 -0.0187 核，另计采样器自身 CPU。采样组的采集 CPU 低于未采样组，视为短测波动，不能归因为脚本降低采集负载。短时间、节流负载的差异不能证明吞吐加速或严格的 P99 回归界限。

首次探索实验发现高频状态输出有可测开销；曾尝试缓存未变化报告，复测没有 CPU 改善且 RSS 增加，最终移除缓存。当前代码没有该缓存。最终数据重新测自保留哈希的最终 release 构建。

基本采样仅测一个 host-status 目标，没有选择磁盘，也不启用 perf。不能直接外推到三机 Docker PID 解析、实际磁盘计数或 DWARF 采样。采样器统计窗口 CPU 不含 Python 导入/参数解析；另提供含启动的进程总 CPU 和子进程 CPU。

## 正确性与实机限制

完整工作区 Rust、63 项外部集成检查、全部目标 Clippy/格式检查通过；Python 离线检查 318 项通过（1 项跳过），新增 Linux 采样集成检查通过。生产 Rust 行覆盖率 18664/18840 = 99.0658%，原口径及 99% 门禁未改。

新增测试核对：同步/异步模式观测开关的全部录制文件逐字节相同；两轮实际图像/IMU 读回数量；活跃等待期间可读取报告；并发乱序完成不会遗漏事件；有界历史与覆盖计数；实际写入/fsync/rename 故障对应分段错误，同时不提前确认持久化前缀。既有损坏拒绝、SIGKILL、尾部忽略和恢复测试继续通过。最终尾段使用同步检查点，异步 dispatch/join 次数不包含它。

同轮全量测试暴露已有 IMU 启动排除测试的 50 ms 窗口竞态：25 Hz 首次回调未必在窗口结束前被排空。仅该功能测试把 discovery 调为 300 ms 并保留排除断言，不修改生产超时或 IMU 策略。

采样脚本已验证状态输入上限、输出上限、私有权限、PID 身份、事件缺口/会话重置、磁盘计数单位、缺失指定磁盘报错，以及停止自己的采样/perf 组时不影响采集进程。模拟 perf 测试只验证生命周期，不冒充真实栈。实际 perf 命令通过参数解析，但当前 Docker 内核的 cpu-clock 事件被拒绝（Operation not permitted）；未放宽权限、修改内核或测得真实 perf 开销。实机必须核对 perf report、线程映射和时间锚点，再用等负载 A/B 验收额外成本。

磁盘请求均值来自整台指定块设备，无法单独归因于录制 fsync；分段 wall/CPU 差值也不能独立证明磁盘是根因。采样数据用于关联和定位，不能认证相机无丢帧、物理同步、下游送达或持久性。

## 复现

在 Linux `/work` 检出目录构建 release 服务及 `service_supervision` 测试驱动，另保留基线 `capture-service`。设置 `GDP_CHECKPOINT_BEFORE=/absolute/baseline/capture-service` 和 `GDP_CHECKPOINT_BENCH_OUTPUT=/absolute/new-result.json`，运行该 release 测试驱动的 `--exact checkpoint_observation_benchmark --ignored --nocapture`。该显式忽略测试不在 CI 做噪声性能门禁。实机采样无需运行此模拟基准，使用上方采样说明即可。
