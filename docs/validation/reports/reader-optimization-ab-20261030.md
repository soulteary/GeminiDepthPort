# 校验读取器优化与 CPU 细分 — 2026-10-30

基线 `8fae5ed2147293cbdc3abb94e9ca57825c148efa`。生产基线没有修改；公共基准仅移除旧 API 不存在的测试专用 PROFILE_BEGIN/PROFILE_END 区块。CPU 细分另用仅插桩、不含优化的基线，其[可复现补丁](reader-profile-baseline-20261030.patch)和二进制 SHA256 与正常基线区分保存。[完整数据](reader-optimization-ab-20261030.json)；[诊断工具及复现说明](../../development/recording-reader-profile.md)。

## 实现与保障

验证路径先检查 JSON 键唯一性，再直接构造类型，不创建完整 serde_json::Value 中间树。未转义键借用输入，BTreeSet 保持 O(log n) 查找；转义后的等价键仍判重复。文档大小、递归、有限数字、schema、未知字段、IMU 进度和数据绑定继续校验。物化消费路径保留原来的 Value 解析作为对照。

V3 验证复用 evidence 缓冲，临时 FrameContext 改为借用；分块名检查避免格式化临时字符串。只在已知文件位置等于目标 offset 时省略 seek，定位/读取失败即清空位置知识。没有跨帧或跨轮缓存成功哈希，没有改 SHA256 算法、格式、屏障、未提交窗口、队列上限或恢复规则。V3 的已封口前缀实际读回加最终实际全量读回均保留；files-v2 保持其原有最终校验。

## 正常路径性能对照

Linux ARM64 Docker，Rust 1.90 release/thin LTO，固定缓冲 64 KiB。3 种数据集各 7 次 before/after，逐轮反转顺序，共 42 个独立进程。compact 为 640×400、512 对、500 MiB 图像；wide 为 1920×1080、64 对、506.25 MiB。compact+IMU 每路时间戳间隔 5 ms，每三对分别附 6/7/7 条样本，对应 200 Hz 与名义 30 FPS 的比例。无真实 SDK/USB/DDS/ROSbag2，不是实际相机的采集 CPU 测量。

两版均启用同样的 V3 检查点流水线。计时包含创建、追加、两轮验证和提交；CPU 为进程全部线程 user+system 时间，峰值 RSS 是 /proc/self/status VmHWM，采样点在后续独立物化比较前。格式/索引/evidence 产物一致，子进程实际逐帧读回比较深度。没有并行编译或其他测试；不预先丢弃首轮，也不丢弃异常值。性能阶段关闭细分计时、分配统计与 LD_PRELOAD。

以下是七轮中位数。P99 为固定直方图区间两端的中位数，不是精确量化；验证累计墙钟可与追加重叠，不能与总墙钟相加。

- compact，无 IMU：CPU 时间 0.5802 → 0.5776 s（-0.5%）；追加 P99 [0.721, 0.786] → [0.786, 0.852] ms；验证 396.52 → 388.11 ms；峰值 RSS 4104 → 4232 KiB；缓存文件系统吞吐 1207.5 → 1221.3 MiB/s。
- compact，含 IMU：CPU 时间 0.5867 → 0.5785 s（-1.4%）；追加 P99 [0.852, 0.918] → [0.786, 0.852] ms；验证 408.77 → 391.59 ms；峰值 RSS 4244 → 4308 KiB；缓存文件系统吞吐 1182.9 → 1226.6 MiB/s。
- wide，无 IMU：CPU 时间 0.6252 → 0.5766 s（-7.8%）；追加 P99 [5.243, 5.494] → [5.243, 5.280] ms；验证 387.89 → 381.26 ms；峰值 RSS 7644 → 7768 KiB；缓存文件系统吞吐 1140.3 → 1263.8 MiB/s。

收益不均匀。含 IMU 的验证墙钟减少约 4.2%，但纯图像 compact 的追加 P99 向上移动一个直方图桶，约 66 μs；RSS 增加 64–128 KiB，不能宣称内存峰值下降。wide 的 P99 区间重叠，不能根据上界变小声称确定的尾延迟改善。单轮约 0.4 s，CPU 有明显波动：wide 的 before CPU 为 0.557–0.763 s，after 为 0.560–0.644 s；中位数下降 7.8% 不是稳定加速保证。

## CPU 热点与计时开销

正常 A/B 后另做 18 个诊断子进程：3 种数据各 3 轮 before/after，每个额外执行一次关闭、一次开启细分计时的实际验证，交替顺序。细分只覆盖读取调用，排除 source open/drop；它不代表完整检查点生命周期。image_read、image_sha256 是 image_read_hash 子项，read_call 又包含所有子项及测量开销，不能累加这些父子统计。

- compact，无 IMU：索引解码 CPU 2.341 → 2.045 ms；evidence 解码 3.060 → 2.832 ms；SHA256 更新 168.91 → 169.48 ms。
  同组单轮读取 CPU，关闭/开启计时：before 185.67/233.65 ms，after 201.21/234.25 ms。
- compact，含 IMU：索引解码 CPU 6.817 → 5.005 ms；evidence 解码 3.111 → 2.915 ms；SHA256 更新 168.87 → 170.41 ms。
  同组单轮读取 CPU，关闭/开启计时：before 190.42/240.24 ms，after 188.16/239.48 ms。
- wide，无 IMU：索引解码 CPU 0.386 → 0.310 ms；evidence 解码 0.474 → 0.428 ms；SHA256 更新 170.61 → 170.75 ms。
  同组单轮读取 CPU，关闭/开启计时：before 182.84/222.43 ms，after 180.56/220.38 ms。

SHA256 是主要计算成本，没有被减少或跳过；含 IMU 索引解码 CPU 减少约 26.6%，但解析不是整体主导项。细分计时使读取 CPU 增加约 16%–27%，因此默认关闭，不能拿插桩数据替代正常路径性能。纯图像 compact 的三轮独立读取 CPU 中位数反而由 185.67 增到 201.21 ms；这组数据不支持所有读取场景 CPU 都下降。正常 A/B 的全过程数据与诊断单轮读取范围不同，均保留原始结果，不择优汇报。

## 临时分配与文件定位

另用独立计数分配器，对 128 对 compact 的 validate_next 到 EOF 统计三次，排除 source open/drop；不把带计数器的耗时作为 CPU 性能。三次一致：分配申请（含 realloc）23476 → 8377，减少 64.3%；累计申请字节 2734547 → 1911859，减少 30.1%。realloc 单独计数为 849 → 1109，增加 260；总申请仍减少。累计申请不等于活跃堆、RSS 或内核分配。

再用只读 lseek/lseek64 拦截器独立测量；以 COMPLETE 出现为界，排除写入期间的两轮验证，仅统计后续 128 对读取。三次均为 384 → 256 次 payload seek，减少 33.3%。这些记录仍全部实际读取并校验。

## 验证

最终 Linux 全工作区测试、63 项外部集成检查、全目标 Clippy 和格式检查通过。生产 Rust 行覆盖率 18880/19063 = 99.0400%，原过滤口径和 99% 门禁未改。macOS 读取器单元及集成测试也通过；修正原有非法 clock ID 测试对 unsigned clockid_t 的编译兼容性，不修改产品时钟策略。

新增测试覆盖严格 JSON 语义与原解析器一致、转义重复键、嵌套重复键、有限数值、大小/递归限制、未知字段和类型错误；实际 evidence 的 f32 舍入中点及 f64 负零/次正规值与原 Value 转换按位一致；连续/非连续位置及部分读取失败后的重新定位；最大/非法分块名；计时默认关闭、启用时机及错误计数；实际 payload seek 调用减少。既有跨块、混合物化/验证、IMU 双轮计数、哈希损坏、SIGKILL、提交故障及恢复测试继续通过。42 次性能子进程同时核对双轮图像/IMU 数量和完全相同的元数据产物。

新增只读 profile_recording 示例验证完整与恢复前缀各 128 对；对每个文件计算 SHA256，工具运行前后完全一致；完成输入的恢复模式被拒绝。工具的附加诊断读取不替代生产双轮读回，也不创建 COMPLETE。

这次确定性改善主要是分配和定位次数减少。整体 CPU/尾延迟收益较小且受负载与调度影响，RSS 有小幅代价。真实录制应在相同 SDK、IMU、图像配置、磁盘与缓存条件下使用关闭细分计时的版本做长时间交替对照，再结合已有检查点采样确认；本报告不证明真实磁盘吞吐、相机无丢帧或实际采集 CPU 加速。
