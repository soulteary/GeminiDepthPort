# 当前能力与已知限制

适用于包含 `dde3e1a` 的主线。以下区分已经实现的功能与仍未完成的实机验收；历史结果按各自报告的提交、镜像和设备范围读取。

## 可以使用的入口

- **部署和日常管理**：按[部署指南](deployment.md)安装，通过 Web 或 `deploy.sh` 配置、预览、确认和启停一至三台相机。默认后端是官方 ROS 驱动；Rust 后端需显式配置。
- **图像消费**：按[消费指南](consumer-integration.md)接收图像、内参和元数据。消息时间、单位和坐标系见[相机接口](../interfaces/camera.md)。
- **IMU**：Rust 后端支持显式启用加速度计、陀螺仪和 ROS 发布。需要实际设备支持相应频率、量程和时钟，配置见[相机配置](configuration.md#rust-相机-imu)。
- **录制和校验**：外部 ROSbag2、原生完整帧对录制、离线校验和前缀恢复各有独立入口，先读[录制指南](recording.md)。

Web 支持选择相机型号、采集后端和镜像标签；切换需先停止全部预览与正式相机，保存后重新构建／预览确认。Rust 后端可按相机配置 IMU 和原生完整帧对录制；录制最终验收与恢复仍使用独立工具。现有部署改动前先结束录制、释放保护并停机，具体步骤见[Web 指南](web.md#切换型号或后端)。

## 持续录制尚未完成正式验收

**三相机原生持续录制的 `RAW_QUEUE_OVERFLOW` 尚未关闭。** 已修正部分软件反压和观测问题，但最近的软件回归、短合成对照及 CI 成功不能替代三相机六组长测和独立恢复验收。

`dde3e1a` 修正了半额度提前等待及 checkpoint 期间后续索引刷写的问题。索引元数据缓冲在 pending checkpoint 期间最多为 2 MiB，帧队列、全局载荷额度、心跳和同步保障保持不变。受控索引争用测试有改善；普通负载未证实通用收益，状态持久化开启时追加 P99 的本轮观测反而变差。连续慢 fsync 注入仍会溢出。具体数据见[该次验证报告](../validation/reports/checkpoint-overlap-20261107/README.md)。

需要可靠持续录制的部署，应在实际设备、磁盘和任务负载下完成[录制验收](../validation/README.md#录制与恢复验收入口)，再确定可接受的运行范围。失败组、未执行组和恢复前缀分别记录，不标记为完整录制。

历史实测还出现过深度序号缺口。原生／DDS 匹配和落盘哈希一致只说明收到的数据相符，源序号连续性需要单独检查；源缺口拒绝规则见[验收门禁记录](../validation/recording-readiness.md#源端缺帧与存储门禁)。

## 时间、配对与同步

- `complete` 保留有效单流 ROS 图像；`strict-rgbd` 仅发布通过检查的完整帧对。原生录制仅保存完整帧对，V2/V3 目录格式均不改变这一限制。
- `pairing.clock` 和 `max_delta_us` 检查同一 SDK frameset，不提供跨 frameset 或跨相机缓冲配对。
- Global 时间映射表达消息时间；硬件曝光同步预设尚未实现，启用 `hardware-sync` 会被拒绝。
- Global 来源就绪后失效会报错，不逐帧回退到 System 时间。

配置方法见[采集预设](configuration.md#rust-采集预设)，时钟和消息定义见[相机接口](../interfaces/camera.md)及 [IMU 契约](../contracts/camera-imu-v1.md)。

## 其他验收边界

- Rust 后端暂不支持通过管理配置修改曝光、增益、滤波和旋转等官方参数，允许项见[后端指南](rust-backend.md)。
- 旧镜像或缺少 `usb_recovery` 的独立配置可能在异常退出后首次重开无帧。已有修复的启用条件和历史实测见[验证索引](../validation/README.md#其他实机记录)。
- D2C 尚未证明与官方 SDK 等价；输出溢出仍按错误处理。
- 当前记录未完成最终发布产物的生产规模长稳、真实拔插／掉电、干净安装、开机、升级回退及业务消费者兼容的整套验收。
- 物理深度精度、手眼标定、硬件曝光同步、跨发行版兼容和无内存泄漏不在现有结论内。
