# Web 配置与预览

部署完成后访问 `http://127.0.0.1:8765`。Web 与 CLI 共用配置、操作锁和录制保护；
不要为同一部署同时启动多个管理服务。安装和远程访问见[部署指南](deployment.md)。

## 配置相机

1. **扫描设备**：从 Linux USB sysfs 读取型号和身份；型号不明确时不允许猜测绑定。
   Gemini 305 仅供 Rust 后端使用，其他型号以档案与后端支持范围为准。
2. **选择型号并绑定槽位**：选择该槽位的型号，再从扫描到的匹配设备中选择序列号。Gemini 305 仅在 Rust 后端可选。
   命名空间和光学帧前缀独立填写，不能冲突。
3. **保存参数**：填写实机支持的流、尺寸、FPS、格式、时间来源和健康策略。
   两种后端均可编辑允许的曝光／增益。Rust 自动曝光提供“沿用／开启／关闭”，手动设置必须显式关闭对应自动曝光；启动后可查看固件版本、属性范围及读回结果，见[设备能力](rust-backend.md#设备能力与曝光增益)。
4. **启用设备**：只有启用设备参与正式采集，默认模板均未启用。

保存会使相关相机的旧确认失效，并停止其不再匹配的预览；共享配置变化可能使全部
确认失效。保存不重启正式服务，多窗口旧 revision 会被拒绝，需重新读取后再编辑。

## 切换型号或后端

这两项选择仅提供给 schema v2；旧配置先按[迁移指南](migration-v1.md)迁移。
先结束录制并释放保护，停止所有预览和正式相机。后端对所有槽位生效，型号按槽位设置；
界面修改只保留在草稿中，点击“保存配置”才提交，不自动停机或启动设备。

- 更换型号会清除本槽位的绑定、启用状态和档位确认。重新绑定设备、核对候选宽高／FPS 并启用后，再保存和预览；界面不猜测实际支持档位。
- 切换后端需核对镜像标签。界面提供不同的官方／Rust 默认标签，可自行填写；保存不会构建镜像，之后仍需执行“构建镜像”并重新确认全部启用设备。
- 兼容参数保留。若切换需要移除不兼容参数，确认框列出相机及参数名，取消则不应用该选择。新提交的参数仍经过原有校验，确认移除不能绕过后端限制。
- 首次切换 Rust 时初始化兼容服务策略：SDK 默认同步行为、System（`host`）时间来源。界面显示启动和心跳预算，保存前先核对。可随后选择 `complete` 或 `strict-rgbd` 等采集预设。编辑既有 Rust 配置不会重置其心跳、配对和服务预算；保存前改回原后端也会恢复原镜像和 Rust 策略。
- Gemini 305、已启用 IMU 或原生录制的配置不能直接切回官方后端。更换实际设备／型号或关闭 IMU 和原生录制后，再执行切换；界面不静默关闭 IMU。

运行中、预览未停止、存在录制保护、配置 revision 过期或新绑定与型号不符时，保存会被拒绝。
切换不迁移已运行实例，旧 generation 保留；新版本仍通过构建、档位确认和正式启动流程生成。

## 预览与档位确认

正式服务停止后，启动所选相机的临时预览容器。预览订阅真实 ROS Image，提供彩色
JPEG 与深度伪彩色；可以逐台预览并切换查看。

执行“检查出帧并确认此档位”时，管理器核对当前配置、镜像与容器实例，再检查所有
启用流的消息布局、尺寸、帧率、时间推进、新鲜度和 QoS。检查通过才保存确认。
确认后可以启动采集；录制完整性仍按[录制指南](recording.md)单独检查。

JPEG 编码最高每流 5 FPS；宽度超过 960 像素时仅缩放显示副本，不修改正式图像。
深度伪彩显示范围为 0.2–3.0 m，无效值为黑色。
超过 3 秒无新图像时不再展示旧帧。临时目录 `work/web-preview/` 只保留最新画面，
不能作为录制数据集。

浏览器停止请求状态约 120 秒后，管理器回收预览；管理进程异常退出时，容器内租约
也会有界结束采集。正常停止会等待驱动退出后移除容器。

## 正式运行

全部启用设备完成确认后，先停止所有预览，再执行“检查并启动相机组”。管理器逐台
启动和检查，最后复查整组。正式采集不会隐式抢占预览或重启已健康的相机。

已有录制保护时不能修改配置、启动预览或停机。任务失败通过状态和“查看日志”定位，
日志可能包含运行信息，不要公开上传。常见问题见[故障排查](troubleshooting.md)。

Web 是管理入口，不是常驻 ROS 数据网关；停止 Web 不应被当作相机录制已结束。
整组停机应使用[受管生命周期命令](lifecycle.md)。

## IMU 与原生录制

schema v2 的 Rust 配置页按当前相机提供两组设置。修改前结束录制、释放保护，停止全部正式服务和预览；保存后重新预览确认受影响相机，再生成部署配置并启动。

- **IMU**：启用加速度计／陀螺仪，设置各自采样率、量程、frame ID、队列容量及过期时间。先选择明确的采集策略和时间戳来源；候选值不代表设备支持，SDK 启动时继续检查能力。保存检查 frame ID 唯一性和两轮轮询的队列容量，不自动增大队列或心跳期限。
- **原生完整帧对录制**：显式启用后，在正式服务启动时创建新的录制会话。选择 files-v2／chunked-v3、任务名、帧对数／字节数上限和有界队列；后台检查点仅支持 chunked-v3，full-credit 批次要求启用流水线。不能与 complete 采集预设共用，改用 strict-rgbd 或原有完整帧对策略。界面不会替你切换采集策略。

保存目录为部署目录下的 `state/native-recordings/<相机名>`，在容器内映射为 `/native-recordings`；每次启动产生独立会话。预览不写录制，关闭录制配置不删除历史文件。达到帧对数目标后排空、读回并提交；提前停止留下未完成任务。任务名、上限和剩余磁盘空间需按实际负载安排。

三机持续录制仍有未关闭的队列溢出。开关配置与 CI 通过不代表实机长测验收通过。原有时间戳校验、队列上限、同步屏障、读回、逐帧哈希和恢复规则保持不变，具体见[录制指南](recording.md)。

## 界面以外的功能

Web 尚不提供录制最终验收、前缀恢复或保护凭据管理表单。
“采集质量事实”按钮显示查询摘要，不启动录制。操作入口见[IMU 配置](configuration.md#rust-相机-imu)
和[录制指南](recording.md)。完整能力及未完成的实机验收见[当前状态](current-status.md)。
