# 属性预检异常的只读取证

本次修正针对合法写入请求在 SDK 范围当前值预检阶段失败、独立 getter
尚未执行的情况。它补充证据，不把越界的当前值解释为合法写入依据。

范围查询失败、结构错误和当前值越界后，若 READ 支持已确认，仍执行独立
getter。写支持查询失败也遵循此规则；READ 未确认时不尝试读取。原始失败
及独立 getter 的返回值、错误、单调时间分别保留，预检异常时不调用 setter。

可选诊断 SDK 增加实际 V4L2/libuvc 读取观测，使用固定大小的线程局部缓冲。
厂商 SDK 无接口时显式报告不可用。诊断 SDK 的新补丁独立校验 SHA256，
原补丁、历史报告、失败日志和证据包不变。具体字段见 Rust 后端使用指南。

本地验证包括：Python 全量 578 项（27 项按平台/环境跳过）、Web 表单回归、
Rust SDK/采集单元及 ABI 回归、Rust 1.85 Clippy、补丁应用检查和真实 C++11
双编译单元观测 ABI。故障覆盖范围异常与成功/失败 getter 组合、底层失败、
事件溢出及非法后端；断言不写属性、不发布图像。Linux 服务回归另覆盖私有
失败报告和诊断成功后原生录制快照；由 CI 执行。

未执行相机实测。旧报告的 range.current=256 原因不能由本次合成回归确认。
后续使用新诊断镜像，在新目录回传独立 getter 和实际底层结果，再判断 SDK、
UVC 或设备行为。严禁用自动 AE 切换、钳位、放宽写入校验代替取证。
录制保护、两轮实际读回、哈希与崩溃恢复路径未修改。

## 等待链与 exposure 覆盖补充

诊断构建上下文现在显式放行 `uvc-observations.patch`，构建记录与运行清单
同时校验其 SHA256。CI 另外实际构建诊断 SDK 和驱动，并在无设备条件下运行
ABI 与清单检查，避免只有生产镜像通过而诊断输入遗漏。

XU 响应新增 operation=4（libuvc GET）和 5（V4L2 XU GET）事件。`value` 是
响应前至多四字节的 little-endian 原始前缀，不是解码后的 exposure；实际属性值
仍以独立 SDK getter 为准。底层失败不信任该前缀。非 UVC 路径或无事件时仍明确
保留空事件，不能补记覆盖完成。接口 ABI、每次八事件上限和严格写入校验不变。

Web 提示先显式关闭对应 AE、手动数值留为 −1，应用后停止并重新启动查询；
确认当前值与范围正常后再申请手动值。第一次启动报告保留的是写入前快照。
联合请求不会先写 AE 以绕过预检，软件也不自动切换 AE 或重试。

checkpoint 的 `verify_wait` 新增 `credit_at_wait`，记录 join 开始前该 writer
自己的 pending/active pair 与字节数及原有限额。它是标签，不参与额度判定，
也不是跨三进程的共享池。完成事件的结束时间与 ok 表示该次 join 返回，不能
推断为向另一个 writer 转移额度。失败瞬间的活跃上下文也包含这份有界快照。

## 队列历史与主机身份关联

开启 checkpoint_observation 时，完整 pair 队列在原互斥区内记录 enqueue、dequeue、
written、overflow、close、abandon 的单调时钟、队列深度、字节占用、最老队龄和
pair 序号。历史固定 512 条，预先分配，不复制像素或 IMU，不在这些操作中写文件。
关闭观测时不记录。状态发布仍走既有后台持久化；历史中的事件时刻与状态读取时刻
分别保留。历史被覆盖或没有包围所选窗口时，分析不能声称重建完整积压过程。

host_kernel_trace.py 与 host_trace_analysis.py 将现场使用的主机工具整理为受控入口。
采集要求显式指定源提交、文件系统 UUID、磁盘和新目录；默认仅采集 fsync/fdatasync
及 scheduler/lifecycle，不采 writev。主机流由观察器种子和实际绑定 writer TID 过滤，
event-fork 跟随后代；helper 后代也可能出现，只有经 proc 身份和生命周期证明的
writer 线程才能关联。设备流保留 ext4/jbd2/block 的整设备上下文及内核线程。

新线程 fork 事件到达时立即尝试读取稳定的 proc 身份和 NSpid，检查 worker 起始
时刻、TGID、PID namespace 与容器 cgroup，减少短命 checkpoint 线程被周期盘点漏过。
读取失败仍明确保留，不按 comm 或父进程猜 namespace TID。重复库存只为已知线程
读取轻量 start_ticks；PID 重用会建立新代际。窗口外身份缺口单列但不删除，窗口内
缺口仍阻止完整关联。空 errors 对象和数组兼容；单个观察器的早期历史不冒充最终
合并事件丢失，实际 lost_events_after_start 和合并缺口继续检查。

checkpoint 同线程 fsync 缺失、内部队列历史不完整都会阻止完整关联。上述工具
不授予录制、两轮读回、哈希或恢复通过结论。新增三 writer 连续 index_sync 屏障
测试在前序积压后施加至少 400 ms 延迟并保持屏障至原队列溢出，再检查收尾与
两轮 prefix 恢复读取；合成结果不代替实机验收。

历史事件按 `columns` 声明的列顺序保存为紧凑数组，官方分析器会还原为具名字段。
这减少每次状态序列化重复生成字段名的开销。已有线程的 proc 锚点只从采样结束
时刻起有效，`birth unknown` 会保留在代际报告；捕获前的出生历史不冒称完整。

CI 外层独立故障用例串行执行，避免两个三 writer／高频 IMU 用例互相叠加负载；
用例内部的三 writer 并发、200 Hz 输入、队列上限和原期限断言均保留。故障选择器
使用最多 4 MiB 的流式扫描并保留分块交界，避免大状态文件越过原 64 KiB 扫描边界
后目标注入未发生。选择器只在测试子进程内生效，不修改生产写入行为。
